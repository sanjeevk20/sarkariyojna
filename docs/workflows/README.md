# Sathi Workflow Guides - Index

Step-by-step citizen guides (English + Marathi) and team system workflows for Maharashtra and central government services. Each page has a citizen guide image, a Marathi version, a Mermaid system diagram with Sathi touchpoints, and a stage table.

> **Status:** **all 26 guides checked on 27 Oct 2026** (3 batches) against news, district/central government pages and secondary sources, with corrections applied; see each page's *Verification* section. Maharashtra state portals were not reachable from the research environment, so final confirmation against current GRs is still needed, and **Marathi text still needs native-speaker review**.

> **Other states:** Uttar Pradesh, 12 guides (English + Hindi) in [`up/`](up/README.md); Karnataka, 10 guides (English + Kannada) in [`ka/`](ka/README.md); Madhya Pradesh, 10 guides (English + Hindi) in [`mp/`](mp/README.md).

## Quick routers

- **Age:** below 65 and destitute → [Sanjay Gandhi](sanjay-gandhi.md); 65+ → [Shravanbal](shravanbal.md); 70+ health → [Ayushman Vay Vandana](ayushman-card.md)
- **Housing:** village → [PMAY-Gramin](pmay-gramin.md); city / town → [PMAY-Urban 2.0](pmay-urban.md)
- **Farm irrigation grants:** SC / Nav-Bauddha → [Krushi Swavalamban](krushi-swavalamban.md); ST → [Birsa Munda](birsa-munda.md); farm pond for any farmer → [Magel Tyala Shettale](magel-tyala-shettale.md); then a solar pump → [Magel Tyala Saur Krushi Pump](saur-krushi-pump.md)
- **Business loan:** open category → [Annasaheb Patil](annasaheb-patil.md); SC / Nav-Bauddha → [Mahatma Phule Mahamandal](mahatma-phule-mahamandal.md)
- **Health:** make the [Ayushman card](ayushman-card.md) first, then use it under [MJPJAY](mjpjay.md)

## Adding a new guide

1. Write `<name>_content.py` (copy any existing one).
2. Run `python3 gen_guide.py <name>_content.py` to produce `<out>.html` and `<out>-mr.html`.
3. Render the guides to PNG with [`render.js`](render.js) (needs Playwright + Chromium):
   `node render.js <out>.html <out>.png '#page'` and `node render.js <out>-mr.html <out>-mr.png '#page'`.
4. Render the Mermaid system diagram to an SVG page (e.g. via Mermaid Live or mermaid-cli), then `node render.js <diagram>.html <name>.png svg`.
5. Add a `<name>.md` page (guide images, Official links table, diagram, stage table, Verification section) and add a row here.

After adding or changing a guide, rebuild the website: `python3 ../site/build_site.py`.

To rebuild every guide after a content change: `for f in *_content.py; do python3 gen_guide.py "$f"; done`, then re-render the PNGs.

## Feedback from readers

Every guide on the website ends with **Did this guide help you? Yes / No** and **Report an error**.

- **Report an error** opens the [guide error form](../../.github/ISSUE_TEMPLATE/guide-error.yml) as a GitHub issue labelled `guide-error`, with the guide filled in. Fix the guide, re-check its sources, update its Verification date, and close the issue.
- **Yes / No counts** use [GoatCounter](https://www.goatcounter.com) (free for non-commercial use, no cookies, no personal data). They are off until you create a GoatCounter site and add its code as the repository variable `GOATCOUNTER_CODE` (Settings → Secrets and variables → Actions → Variables). The next deploy turns counting on: page views per guide, plus events `/feedback/<guide>/yes` and `/feedback/<guide>/no`.
- The page shows each guide's **Verification** date and how many of its official links are confirmed on government pages, so readers can judge how much to trust it.

## "Am I stuck?" status checker

The website's **Am I stuck?** page (`#check`) lets a citizen pick a scheme and the status they see. It explains the stage, gives the next step, and, when the file is overdue or blocked, drafts a complaint in English or the scheme's local language, addressed to the right office. It runs entirely in the browser and stores nothing.

Citizens can also **paste their status text or SMS**. Sathi then picks the matching stage and the latest date in the text. Each stage's `match` phrases in `tracker.py` drive this. Add the exact wording people see on the portal or in SMSes, in English and the local language.

It currently covers PM-KISAN, Income certificate (UP), Ladki Bahin, Gruha Lakshmi and Ladli Behna (MP). To add a scheme, add an entry to [`../site/tracker.py`](../site/tracker.py). Take its stages, time limits and offices from that scheme's guide and Verification notes. Then run `python3 ../site/build_site.py`. The build fails if a tracker points at a guide that does not exist.

## "Where are people stuck?" map

The website's map page (`#map`) shows, by district, for Maharashtra, Uttar Pradesh, Karnataka and Madhya Pradesh:

- **News signals** from [`../site/signals.py`](../site/signals.py): news reports of anti-corruption bribe arrests and of stuck payments, each with its source link. State-wide signals are listed under the map. Add new ones there; the build fails if a district name does not match the boundaries.
- **Citizen reports.** After an "Am I stuck?" result, a citizen can choose district, office and whether money was asked, then send it. This opens the prefilled [status report form](../../.github/ISSUE_TEMPLATE/status-report.yml), which becomes a GitHub issue labelled `status-report` with no name or numbers. On every deploy the Pages workflow totals these issues per district. A district's figures (reports, % overdue, % asked for money) appear only from **10 reports**, so no single person's case can be picked out.
- **Boundaries:** Census 2011 districts from [DataMeet](https://github.com/datameet/maps) (CC BY 4.0), simplified by [`../site/build_geo.py`](../site/build_geo.py) into `../site/geo/districts.json` (182 KB). Re-run it only to change states or boundaries.

These are signals, not proof. An arrest is an allegation until a court decides. Officers are never named on the map.
